What makes Bolt different

Not five separate projects bolted together — one small codebase, one grammar, five ways to run it.

▶

Bytecode VM

The default engine. Compiles to bytecode, runs on a stack machine with an explicit call-frame stack — no Python recursion limits on deep Bolt recursion.

🌐

Native compiler

Opt-in --native AOT-compiles number-only functions straight to C, built with gcc or MSVC, running at genuine C-speed.

✨

JS transpiler

--target js compiles Bolt straight to a standalone .js file — runs in Node or any browser, no dependencies.

📡

Built-in web server

serve() answers real HTTP requests with dynamically computed responses — no framework required.

📦

Python interop

pyimport() borrows an allowlisted slice of Python's real standard library directly, instead of reimplementing it.

🎮

Game dev primitives

Real windows, drawing, sprites, tilemaps, a camera, mouse/keyboard input, collision detection, and sound — GPU-accelerated via SDL2 on Windows, tkinter fallback elsewhere — window() and friends.

⚖

Native C interpreter (new, experimental)

native/bolt.c is a from-scratch interpreter with zero Python dependency at runtime — verified against the Python implementation on real scripts. Covers core language + Win32 game builtins; no typing/tensors/pyimport() yet.

Editor

Bolt Studio: a rebranded VSCodium build with Bolt syntax highlighting, a Bolt Dark theme, a built-in Run & Preview panel, and an AI assistant baked in — the full VS Code experience (file explorer, terminal, git, extensions) plus first-class .bo support out of the box.

Chapter 1

Getting started

Install nothing but Python. Bolt has zero dependencies to run a script — no package manager, no build step.

hello.bo
print("Hello from Bolt")
let name = "world"
print("Hello, " + name)

Run it: python cli.py hello.bo — or python cli.py -i for a live REPL.

Chapter 2

Variables and types

Numbers are always internally floats but print without a trailing .0 when whole. Strings, booleans, and nil round out the basics.

variables.bo
let age = 30
let price = 19.99
let name = "Ada"
let active = true
let nothing = nil
print(age, price, name, active, nothing)
print(type(age), type(name))
Chapter 3

Control flow

if/else, while, and for x in ..., plus break and continue work exactly as you'd expect from Python.

control_flow.bo
let total = 0
let i = 0
while i < 5 {
    if i == 3 { i = i + 1; continue }
    total = total + i
    i = i + 1
}

for n in range(1, 11) {
    if n > 7 { break }
    total = total + n
}
print(total)
Chapter 4

Lists and maps

Lists are ordered, index with [], and for x in list iterates directly. Maps use string keys, also indexed with [].

collections.bo
let nums = [1, 2, 3]
push(nums, 4)
print(nums, len(nums))

for n in nums {
    print("item:", n)
}

let person = {"name": "Ada", "age": 30}
print(person["name"], keys(person))
Chapter 5

Functions and closures

Functions are first-class values. Closures capture their enclosing scope correctly — each call to make_counter() gets its own independent count, not a shared one.

closures.bo
func make_counter() {
    let count = 0
    func increment() {
        count = count + 1
        return count
    }
    return increment
}

let counter = make_counter()
print(counter())  # 1
print(counter())  # 2

# anonymous functions work as values too
let adder = func(x) { return func(y) { return x + y } }
let add5 = adder(5)
print(add5(10))  # 15
Chapter 6

Gradual typing

Annotate what you want checked; leave the rest fully dynamic. A static pass catches type errors before the script runs at all.

typed.bo
func add(a: number, b: number): number {
    return a + b
}
let total: number = add(2, 3)

# unannotated stays fully dynamic
let anything = "a string"
anything = 42  # fine, no annotation here

Type annotations are opt-in per variable or function — Bolt never forces you to type everything.

Chapter 7

Modules and Python interop

import() loads another .bo file as a module. pyimport() borrows an allowlisted slice of Python's real standard library directly.

modules.bo
let math_utils = import("packages/mathutils.bo")
print(math_utils.is_prime(17))

let stats = pyimport("statistics")
print(stats.mean([4, 8, 15, 16]))

pyimport() is restricted to a safe allowlist (math, statistics, json, itertools, and similar) — no filesystem or process access.

Chapter 8

Native compilation for speed

Annotate a function's params and return type as number, run with --native, and eligible functions compile straight to C — real machine-code speed for the hot path.

fib.bo
func fib(n: number): number {
    if n < 2 { return n }
    return fib(n - 1) + fib(n - 2)
}
print(fib(30))

Run it: python cli.py fib.bo --native — needs gcc, or on Windows falls back to MSVC's cl.exe automatically.

let win = window(480, 320, "My Game")
let x = 220

Chapter 1

Overview and philosophy

Bolt is a small, Python-flavored language built around one unusual idea: the same source can run five different ways from one codebase — a tree-walking interpreter, a bytecode VM (the default), an AOT native compiler down to real C, a JavaScript transpiler, and a built-in HTTP server. Most languages get that kind of breadth from separate outside projects (PyPy vs. CPython, V8 vs. SpiderMonkey); Bolt ships all of it together.

The syntax deliberately reads like Python (indentation aside — Bolt uses braces) to keep the learning curve low, while gradual typing and native compilation are opt-in, not required.

Chapter 2

Values and types

Bolt has seven kinds of values: numbers (always float internally, printed without a trailing .0 when whole), strings, booleans, nil, lists, maps, and tensors. type(x) returns a value's type name as a string, and num(x) / str(x) convert between representations where it makes sense.

types.bo
print(type(42), type("hi"), type(true), type([1]))
print(num("3.5") + 1, str(42) + "!")
Chapter 3

Operators

Arithmetic: + - * / % **. Comparison: == != < <= > >=. Logical: and or not, both short-circuiting. + on two strings concatenates; * between a string and an int repeats it.

operators.bo
print("ab" * 3)          # "ababab"
print("a" + "b")          # "ab"
print(7 % 3, 2 ** 10) # 1 1024
print(true and false or not false)
Chapter 4

Functions in depth

Named functions (func name(...) { ... }) and anonymous functions (func(...) { ... } as an expression) share the same closure semantics. Recursion works normally, and since v0.15.0 the VM uses an explicit call-frame stack rather than recursing through Python's own call stack, so deep Bolt recursion (tested to 50,000+ levels) no longer crashes.

Chapter 5

Gradual typing in depth

Annotations are checked by a static pass before execution — let x: number = "oops" is rejected before the script runs at all, not at the moment that line executes. Function parameters, return types, and let bindings can all be annotated independently; anything left unannotated stays fully dynamic, including inside an otherwise-typed function.

Chapter 6

String and list standard library

Roughly twenty built-ins cover the common cases without a module system to reach for. Note that sort() and reverse() mutate their argument in place (and also return it) — a real gotcha if you expected a copy.

stdlib.bo
print(upper("bolt"), trim("  hi  "))
print(split("a,b,c", ","), join(["a","b"], "-"))
print(starts_with("bolt.bo", "bolt"))

let nums = [5, 3, 1]
sort(nums)  # mutates nums to [1, 3, 5]
print(nums, contains(nums, 3), index_of(nums, 3))
Chapter 7

Tensors and numeric computing

A dense tensor type with elementwise ops, dot, matmul, transpose, identity, and tmap (apply a Bolt function elementwise). Works identically across the VM, the tree-walking interpreter, and the JS transpiler target.

tensor.bo
let m = tensor([[1, 2, 3], [4, 5, 6]])
print(tolist(transpose(m)))
print(dot(tensor([1,2,3]), tensor([4,5,6])))

func double(x) { return x * 2 }
print(tolist(tmap(tensor([1, 2, 3]), double)))

No broadcasting and no GPU support yet — this is a real capability, not a NumPy replacement.

Chapter 8

Modules and the package system

import(path) loads another .bo file and returns a map of everything it defines. There's also a small local package registry (mathutils, stringutils, stats) bundled with the repo — a real start on ecosystem/libraries, still explicitly not a full package manager (no registry to publish to, no version resolution).

Chapter 9

Python interop in depth

pyimport(name) loads a real Python standard-library module and hands back a Bolt map of its public functions and constants — the same shortcut Deno took by staying npm-compatible instead of rebuilding a package ecosystem from scratch. Restricted to a curated allowlist (math, random, statistics, json, re, itertools, datetime, string, collections, functools, fractions, decimal, textwrap, unicodedata, calendar, bisect, heapq) — this is a bridge to safe library code, not a general FFI. pyimport("os") fails with a clear error rather than granting shell or filesystem access.

Chapter 10

How execution actually works

The default bytecode VM compiles the AST to bytecode (constant pool, resolved local/global/upvalue slots, jump-patched control flow) and runs it on a stack machine. A Bolt-to-Bolt function call pushes a saved frame onto an explicit call stack and continues the same loop — not a nested Python call — which is why deep recursion no longer crashes. The original tree-walking interpreter is kept as a reference implementation (--engine tree); both engines are tested against the same cases and always agree.

Honest performance note: the default VM is genuinely slow for interpreted code — fib(30) takes roughly 17 seconds, about 100x slower than Python. The bottleneck is per-opcode dispatch cost in a pure-Python loop, not the call-stack design. See Chapter 11 for the escape hatch.

Chapter 11

Native compilation in depth

Any top-level function whose parameters and return type are all annotated number — and whose body only uses arithmetic, comparisons, if/while, for x in range(...), return, and calls to sqrt/abs/floor/ceil/pow/min/max or other eligible functions — is eligible. Eligible functions compile to C, build with gcc -O2 (or MSVC's cl.exe /O2 on Windows without gcc), and load back via ctypes, transparently replacing the interpreted version under the same name.

Measured this way: fib(30) runs in ~0.005s of native execution, matching C (0.003s) and C++ (0.004s) within noise — but only for this narrow eligible subset, not the language generally.

Chapter 12

The JavaScript transpiler

--target js compiles the AST directly to a standalone .js file that runs in Node or any browser with zero dependencies — not a runtime interpreter shipped alongside the output, a real compile step. pyimport() isn't available under this target (no Python runtime to call into in a browser); it fails with a clear error at compile time rather than producing broken JS.

shell
python cli.py fibonacci.bo --target js   # writes fibonacci.js
node fibonacci.js
Chapter 13

Game development toolkit

window(width, height, title) opens a real on-screen window — GPU-accelerated via a bundled SDL2 renderer on Windows, falling back automatically to a tkinter software canvas anywhere that isn't available. tick(win, fps) pumps the event loop, paces to the target frame rate, and returns false once the window closes — while tick(win, 60) { ... } is the entire game loop.

Drawing: clear, rect, circle, line, draw_text, draw_image. Collision: rects_overlap() and circles_overlap().

New in v0.21.0: real Linux support — the SDL2 rendering backend now loads the system's own SDL2 install on Linux (apt install libsdl2-2.0-0 libsdl2-gfx-1.0-0 libsdl2-image-2.0-0) instead of only the bundled Windows DLLs, and beep()/play_sound()/stop_sound() now work on Linux too via SDL2's audio queue instead of Windows-only winsound. Verified with real execution on a real Linux machine, not just parsed. play_channel()'s true multi-channel mixing (built on the Windows Media Control Interface) remains Windows-only.

New in v0.20.0: a camera/viewport (set_camera(win, x, y) — offsets every subsequent rect/circle/line/draw_image/draw_sprite call automatically, draw_text deliberately stays in screen space for HUDs) and tilemaps (load_tileset(), draw_tile(), and draw_tilemap(win, tileset, grid, tile_w, tile_h) — draws a whole level from one Bolt list-of-lists in a single call, with -1 marking an empty cell). Levels pan correctly with the camera for free. See examples/camera_tilemap_demo.bo.

New in v0.19.0: a real GPU-accelerated rendering backend — every drawing/sprite call now runs through SDL2's hardware-accelerated SDL_Renderer on Windows (bundled, zero extra install) instead of tkinter's software canvas, with tkinter kept as an automatic fallback everywhere else. Same public API, no script changes required. See the changelog for the real bugs (a truncated 64-bit pointer, a wrong-by-default color channel order) found and fixed while building it.

New in v0.18.0: sprite animation (load_spritesheet(), make_anim(), anim_draw()), audio mixing (play_channel()/stop_channel() — multiple named channels play simultaneously via Windows MCI, unlike play_sound() which can only play one sound at a time), basic physics (apply_gravity(), physics_step(), clamp()), and a scene/state stack (packages/scenes.bo). See examples/platformer_demo.bo for all four together.

Chapter 14

Mouse, sound, and sprites

mouse_x(win) / mouse_y(win) / mouse_down(win, button) track real cursor position and button state ("left" or "right"). draw_image(win, path, x, y) draws a real PNG/GIF, cached per window by path. beep(freq, duration_ms) and play_sound(path) / stop_sound() give real audio via SDL2 or winsound (Windows) — see Chapter 13 for the backend split.

Chapter 15

The built-in web server

serve(port, handler, max_requests) starts a real http.server.HTTPServer. handler is a Bolt function taking the request path and returning the response body, so every response is computed live by Bolt code. max_requests defaults to 1 (so a demo doesn't hang forever); pass 0 to run until killed.

Deliberately minimal: GET-only, no routing table, no request bodies — a foothold, not a framework.

Chapter 16

Bolt Studio in depth

Bolt Studio is a rebranded VSCodium build (the telemetry-free, open-source build of VS Code) with the Bolt language extension baked in as a built-in extension — not something you find and install from a marketplace. That extension contributes real TextMate-grammar syntax highlighting for .bo files, file icons, and a full workbench color theme ("Bolt Dark": activity bar, tabs, buttons, editor chrome, not just syntax colors) built around the same palette used across this site.

Everything else — file explorer, terminal, git integration, the extension marketplace for every other language — comes free from the underlying VS Code codebase. Available for Windows and Linux (see the Download tab); no language server yet, so no autocomplete or inline type errors inside the editor itself.

Chapter 17

The local package registry

Three small bundled packages ship in the repo's packages/ directory: mathutils.bo (square, factorial, is_prime, gcd), stringutils.bo (title_case, is_palindrome, pad_left), and stats.bo (mean, median, stddev) — loaded the same way as any other module, via import("packages/mathutils.bo").

Chapter 18

What's not there yet

Read honestly, not glossed over: no try/catch in the language itself — a runtime error is fatal, surfaced with a clear message and line number rather than recoverable. No language server (no autocomplete, no go-to-definition). No public package registry to publish to. The default VM is genuinely slow outside the native-compiled path (see Chapter 10). Tensors have no broadcasting or GPU support (rendering is a separate matter — see below). As of v0.21.0 the game-dev rendering/audio path (Chapter 13) works on Linux as well as Windows, on top of v0.20.0's camera/viewport and tilemap rendering, v0.19.0's SDL2 GPU-accelerated rendering, and v0.18.0's sprite animation, audio mixing, basic physics, and a scene/state stack — still no scene *graph* (a rendering hierarchy), no tileset/level file format to import from (Tiled .tmx or similar), no macOS support, no shipped games, and no community around any of it.

None of this is hidden on the Comparisons tab either — see the full report for the same gaps stated in direct comparison to Python, JavaScript, C, and C++.

# generate_page.bo — generates the HTML body for this page.
# Every rating card, bar, and version entry below is built by
# Bolt functions and loops, then printed as one HTML document.

func star_bar(score) {
    let out = ""
    let i = 0
    while i < score {
        out = out + "&#9733;"
        i = i + 1
    }
    let off = 10 - score
    let j = 0
    while j < off {
        out = out + "&#9734;"
        j = j + 1
    }
    return out
}

func rating_row(who, cls, score, best) {
    let badge = ""
    if best { badge = "<span class=\"winner-badge\">best</span>" }
    let winner_class = ""
    if best { winner_class = " winner" }
    let head = "<div class=\"rating-row " + cls + winner_class + "\">..."
    let mid = "<span class=\"stars\">" + star_bar(score) + "</span>"
    let tail = "<span class=\"rating-score\">" + str(score) + "/10</span>" + badge
    return head + mid + tail
}

func rating_card(title, why, rows) {
    let body = "<div class=\"rating-card\">..." + title + why
    for row in rows {
        body = body + rating_row(row["who"], row["cls"], row["score"], row["best"])
    }
    return body + "</div>"
}

func bar_row(label, cls, value, width) {
    let head = "<div class=\"bar-row\">..." + label + value
    let fill = "<div class=\"bar-fill " + cls + "\" style=\"width:" + str(width) + "%\">"
    return head + fill + "...</div>"
}

let versions = [
    {"badge": "v0.7.0", "desc": "Added the built-in serve() web server.", "current": false}
    # ... v0.8.0 through v0.21.0 ...
]
let html = ""
for v in versions {
    html = html + version_item(v["badge"], v["desc"], v["current"])
}

print(html)  # the real Bolt interpreter prints this page's HTML

Install

01

Download

Windows: get BoltStudio-Setup-win32-x64.exe above. Linux: get BoltStudio-linux-x64.tar.gz from a workflow run or release.

02

Run the installer

Windows: double-click it and follow the setup wizard. Linux: extract the tarball and run ./install.sh from inside it — no root needed.

03

Launch

Windows: from the Start Menu (or desktop shortcut). Linux: run bolt-studio or find "Bolt Studio" in your application menu.

Note: the Windows build isn't code-signed, so SmartScreen will likely show a warning — click "More info" then "Run anyway." The Linux build is likewise unsigned/unnotarized; most distros won't warn about that the way Windows does.
